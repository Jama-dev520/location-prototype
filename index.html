Vendor Location List

What the providers actually sent us — every field is read-only, including sweeper, which now arrives with the daily sync. M&MP stores are self-operated, so their owner is the store itself rather than a provider. When a value is wrong, we do not correct it here: we flag it with a reason, the flag travels on this record, and the provider fixes the source. The OC layer only decides whether the location goes live.

OC Location List

The record customers see. Two actions only: enable, and flag an anomaly. There is no editing here — a wrong address does not get typed over, it gets flagged back to the provider. Values are merged per field: an M&MP self-operated store is its own source and wins first, then LMS, then PUDO Inc fills whatever is still empty.

Duplicate Check

A standalone page for one question only: are these two vendor locations the same store? Pairs are detected by fuzzy match (address 50 · postal 25 · city 15 · state 10, threshold 75%). The decision decides the mapping — same store = 2:1 (two vendor records, one OC location, LMS values win), not the same = 1:1 (each gets its own OC location). Every OC location that is fed by more than one vendor record is marked 2:1 in the OC list.

Data Issues

Everything that is wrong with the data, in one ledger — no separate review queues. Three kinds: what we asked the provider to fix, what changed after sign-off, and what never passed intake. The only actions are flag / chase / re-sign: the console never edits a value.

Every create, sync write, flag, decision and sign-off, across both layers. Filterable by layer and type.
