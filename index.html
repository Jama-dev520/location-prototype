Duplicate Review
Cross-provider locations whose addresses are fuzzy-matched (address line 1 + city + state + postal code). Because provider addresses never match exactly, pairs are scored by similarity and flagged when the score reaches the threshold — you confirm whether they are the same physical store. Only confirmed locations receive an OC location ID and sync upstream.

How it works
  • Fuzzy auto-detect — each sync compares every new/changed location against the other provider's catalog. Addresses are normalized (lowercase, punctuation/whitespace-insensitive, unit/suite suffix stripped) and compared by token similarity.
  • Match score — a weighted 0–100% score across address_line1 (50%), postal_code (25%), city (15%), state (10%). Pairs scoring ≥ 75% are flagged as potential duplicates for review; the differing tokens are highlighted in the "Address diff" column.
  • OC location ID — a unique OC-owned identifier. Locations without an OC ID are never synced upstream. A location with no duplicate match gets its OC ID assigned automatically at creation.
  • Confirm = same store — both locations are linked to one OC location ID and become eligible for upstream sync (if active + enabled).
  • Reject = different store — each location keeps its own independent OC location ID; the pair is dismissed as a false positive.
  • Both actions are written to the audit log (OC_LINK_CONFIRMED / OC_LINK_REJECTED).
