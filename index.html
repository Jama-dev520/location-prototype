v2.6.0 changes — provider data is a proposal, not a fact: one Review Center with four decision types (duplicates · data quality · sync changes · sign-off) · a live location keeps its signed-off baseline when the provider changes something · enabling is a checklist sign-off instead of a switch · an operator edit is final: pushed downstream immediately, baseline refreshed, field locked, any pending provider change on it superseded · if nobody acts, nothing changes.
v2.5.0 changes: all editing now happens in modals — store details in one grouped form, opening hours in a structured 7-day editor (multi-range, add/remove, copy to weekdays), sweeper in a small dialog. No more inline form expanding at the bottom of the page.
v2.4.0 changes: detail view returned to a full page (was a 640px side drawer) with tabs and a per-location change history · semantic versioning introduced (major architecture · minor feature · patch fix) — click the version chip in the header to see the full history.

Vendor Location List

Raw provider locations synced from PUDO Inc & LMS. Read-only except Sweeper (who physically picks up packages). Each vendor location generates one OC location ID (unless it is a suspected duplicate). QR dropoff marks LMS stores that accept QR-code drop-off (customer presents a QR code instead of a printed label).

OC Location List

OC-owned, downstream-facing locations, backfilled from vendor records. The enable switch lives here. When a vendor location goes inactive, its linked OC location is auto-disabled and blocked from downstream sync. QR dropoff is backfilled from the linked vendor location.

Change Log

Global audit trail across both layers — every change is traceable to an operator or sync event.

Sync Status

Daily incremental sync from each provider. New vendor locations auto-generate OC locations (default disabled).

Review Center

Everything that needs a human decision before it can reach downstream customers. Four decision types share one queue but have separate rules — because they block at different points: Duplicates block OC ID creation, Data Quality blocks enablement, Sync Changes block field writes, Enable Sign-off is the final gate before visibility. Nothing here can make data more visible by waiting: an unresolved item always keeps the last known good state.

⚠ This OC location's linked vendor location is inactive. It is auto-disabled and blocked from downstream sync. It can be enabled again once the vendor location returns to active.
Version History✕
Semantic versioning — major = architecture change · minor = new feature · patch = fix or copy change. Every delivery is tagged and pushed.
Edit Store Details OC-level override✕
Only edit fields flagged as incorrect. Every change is recorded as STORE_DETAIL_EDIT against this OC location — the linked vendor record is never modified.
Changes become visible downstream after the next sync (PUDO Inc 02:00 · LMS 02:30).
